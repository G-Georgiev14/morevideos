# Coded 3D Toon Short

Make a 30-90 second vertical (1080x1920, 30 fps) comedy story short, animated 100% in code: three.js scenes rendered frame by frame in headless Chromium, encoded with ffmpeg, timed to the user's voice-over, with word-by-word captions and synthesized sound effects. No AI image or video generators.

Reference films: "Death Is My Roommate" (everyman + Grim Reaper, 23 shots, 61 s) and "My Superpower Is Pigeons" (everyman + Kevin the pigeon, town square, giant robot, 30 shots, 57 s).

## The kit

The engine ships with this skill in `kit/` (next to this file): `engine.js` (renderer, toon look with outlines, human / rock / dragon / griffin / critter / giant-robot rigs, town square set with academy, fountain, shops, park bench, race arch, podium and statue pedestal, the framing camera `fit()` that also keeps the camera above the ground, captions and 2D effects), `film-render.js` (storyboard stills, check frames, parts, full render), `film.html`, `align.py` (forced alignment, captions, lip-sync envelope, padded `mix.wav`), `package.json`, `README.md` and `example/shots_dwayne.js` (a complete 33-shot film, "In This Town, Mine Is a Rock"). Copy the whole `kit/` folder into the working folder; a film is built as `cat engine.js shots.js > film.js`. Older installs may instead have `lib.js`, `camera.js`, `sets.js`, `town.js` and their examples; either kit works with this workflow.

If this skill's folder has no `kit/`, look for `toon-short-kit.zip` attached or in a connected folder and unzip it. If neither exists, ask the user to attach it once; if they can't, rebuild the engine from the "Engine spec" section below before doing anything else.

Setup in the working folder: `npm i three` (Playwright and Chromium are usually pre-installed; never reinstall Playwright), `pip install pocketsphinx numpy scipy --break-system-packages`.

**Always ask where to render.** Before the full render, ask the user whether they want to render on their own PC or in the cloud workspace, and wait for the answer. Give the trade-off in one line: the cloud workspace has no GPU and 2 CPU cores (about 4 s per frame, roughly an hour per minute of video, no setup needed); their PC (Windows, Ryzen 5 7430U, 16 GB RAM, integrated Radeon) can use its graphics chip but needs Node.js and ffmpeg installed once.

## Workflow (follow in order)

1. **Story: start with 5 topic ideas.** As soon as this skill loads, before anything else, suggest 5 topic ideas for the video, even if the user only said hello or named a vague theme (use the theme if they gave one, such as "In this town..."). Number them 1-5; each gets a title, the first-person hook line, the co-star (everyman + contrasting supernatural/absurd co-star) and the ironic twist in one sentence, plus which existing characters and sets it can reuse. Ask the user to pick one, mix two, or give their own premise. If the user already gave a full premise, confirm it and skip the list. Ask only what changes the build: premise, any look changes, captions/SFX/music, and framing (default: close-ups allowed, but no face or character is ever cut at the frame edge).
2. **Script first.** Write ~150 words for 60 s in this structure: 0-3 s shocking first-person hook; 3-25 s rule-of-three escalating mishaps; 25-50 s turning point (conflict, panic, emotional beat); 50 s-end ironic twist or cliffhanger. Narrator lines are first-person; co-star lines are in quotes. Send it as ONE paragraph for ElevenLabs, say which lines are the co-star, and suggest voices (energetic young narrator; deep/gravelly co-star). If the user wants one voice only, add short lead-ins ("Then Kevin whispered,") so quoted lines are clear. End the message by asking the user to record it and send the audio file (one MP3/WAV, or one file per voice), and say that the storyboard comes next. Then wait for the audio. Do not animate to estimated timing.
3. **Align audio.** Save the script as `script.json` = `[["N","phrase"],["C","phrase"],...]` (one entry per sentence or clause, in spoken order). Run `python3 align.py <audio> script.json`. It writes `vo.wav` and `data.js` (CHUNKS = caption groups of up to 3 words with times, ENV = loudness per frame, LINES = phrase start/end). Cross-check phrase starts against `ffmpeg -i vo.wav -af silencedetect=noise=-38dB:d=0.18 -f null -` and fix any start that is clearly off. If the user sends separate files per voice, concatenate them in script order first.
4. **Shot list from the audio.** One shot (or two) per phrase, cut on the phrase start minus ~0.05 s. Aim for 18-30 shots per minute; no shot longer than ~4.5 s. For every shot write: subjects to frame (which characters, full body or whole head), the camera move from `camera.js`, and the start/end angle. Camera rules for the list:
   - The camera moves in at least two thirds of the shots (orbit, crane, push-in, pull-out, arc, tracking a moving character, handheld drift on holds).
   - Use the whole 3D world: low angles for power, high angles for defeat, top-down for comedy beats, from behind for reveals, dutch roll for panic, wide FOV for scale (giant things), orbits for big moments.
   - Never repeat the same angle in two consecutive shots; alternate sides and heights.
   - Video length = audio length + 0.5 s, ending on a cut to black.
5. **Build what the story needs.** Reuse existing characters, sets and props; add new co-stars, props or sets in the same style (rounded boxes, capsules, spheres, toon material, outlines). Put new pieces in their own module like `town.js`.
6. **Write `film.js`** from `example/film_pigeons.js` or `example/film_death_roommate.js` (same structure: sets, cast, props, `shot(t0, t1, fn)` list, overlay, `window.renderFrame(t)`). Frame every shot with `camera.js`:
   ```js
   import { bodyBox, headBox, pointsBox, fit, move, moves, blend, applyCam, audit } from './camera.js';
   shot(12.2, 14.7, (u, t) => {
     // ...place characters and pose them first...
     const box = bodyBox([guy, kev]);                               // what must be fully visible
     applyCam(move(box, u / 2.5, { yaw: -0.5, pitch: -0.2, zoom: 1.4 }, { yaw: 0.4, pitch: 0.2 }));
   });
   ```
   `yaw` 0 = in front, PI = behind, ±PI/2 = sides; `pitch` negative = low angle, positive = high, ~1.4 = top-down; `zoom` ≥ 1 (1 = tightest framing that still shows everything); `fov` 22-60; `roll` for dutch angles. Ready moves: `moves.orbit / craneUp / craneDown / pushIn / pullOut / arc / vertigo / hold`. Because the box is measured every frame, the camera follows characters as they move. Use `headBox(rig)` for close-ups (whole head always in frame) and `pointsBox` to include a far or huge object.
7. **Check stills before the full render.** `node render.js still <times>` for the start, middle and end of every shot, tile them into a contact sheet with ffmpeg, and look at it. `camera.js` guarantees the box is inside the safe area, but it cannot see things in the way: fix occlusion (a prop, banner, tree or wall between camera and subject: change the yaw, hide the object for that shot, or move the subject), wrong poses, blow-outs and characters looking the wrong way. Repeat until every shot reads. In a still, `audit(box, framing, camera)` returns 0 when nothing is cut.
8. **Storyboard in images, then wait for approval (required gate).** Once the audio is aligned and the shot list exists, build every shot first as a still (characters placed and posed, camera at its mid-shot framing, no motion yet) and render one real frame per shot at the middle of the shot with its caption (`node film-render.js board`). Never deliver a text-only storyboard. Check the frames (occlusion, blocking, solid-colour frames meaning the camera is inside a building, faces under the caption band), fix, re-render. Then deliver: (a) a contact sheet image of all frames in order, sent as a file, and (b) a storyboard page with each frame beside its time range, voice-over line, what happens and the camera move. Ask the user to approve or name shot numbers to change, and stop. Only after the user approves, move to video production: add the motion (camera moves, character animation, lip movement) and continue with the steps below.
9. **Sound effects.** Copy `example/sfx_death_roommate.py`, keep the synth functions, replace the cue list with cues at this film's times. Mix: `ffmpeg -i vo.wav -i sfx.wav -filter_complex "[0:a]aformat=channel_layouts=stereo,apad=whole_dur=<DUR>,loudnorm=I=-15:TP=-1.5:LRA=11[v];[1:a]volume=0.42[s];[v][s]amix=inputs=2:normalize=0:duration=longest,alimiter=limit=0.95[a]" -map "[a]" -t <DUR> mix.wav`. Without sound effects, make `mix.wav` from `vo.wav` alone with the same padding and loudnorm.
10. **Full render, where the user chose.** Ask first (see "Always ask where to render").
   - **Cloud workspace:** `./all.sh <total_frames>` in the background (10 parts, two workers, concat with `-c copy`, then adds `mix.wav`). Expect roughly 2.5-5 s per frame, so about an hour for 60 s; tell the user the estimate. One encoded file per part, never a PNG per frame.
   - **User's PC:** package a project folder: `index.html`, `lib.js`, `camera.js`, the set files the film imports (`sets.js`, `town.js`), `film.js`, `data.js`, `mix.wav`, `render.js` and `render-all.js` from the kit (`render.js` uses the GPU by default and prints `Renderer: ...`; `CPU=1` forces software), and a `package.json` pinning `three` and `playwright` to the versions used here. Add a README with Windows steps: Node.js LTS, `winget install Gyan.FFmpeg`, `npm install`, `npx playwright install chromium`, test with `node render.js still <t1> <t2>`, then `node render-all.js` -> `final.mp4` (re-running skips finished parts; `$env:WORKERS=3` for more parallel browsers). Test both scripts on a few frames in the workspace first. If the computer is linked and a folder is connected, copy the project there and start the render in a native PowerShell window (the device shell is a Linux VM without the GPU); otherwise send the zip and the two commands to run.
11. **Verify and deliver.** When you can reach the rendered file, make a contact sheet of the final MP4 (one frame every ~2 s), look at it, check duration and frame count with ffprobe, then send or point to the MP4. When the user rendered it themselves, offer to check it if they attach `final.mp4`. Say plainly what was checked (stills) and what was not (motion, audio balance). Offer per-shot re-renders: re-render only the affected part file and re-join.

## Rules that matter (learned the hard way)

- **Framing is solved, not guessed.** Frame shots with `camera.js` instead of hand-placed `cam()` positions. The safe area is the frame minus 6% at the top and sides and minus everything below 66.5% (the caption band), so faces never sit under the captions. Close-ups use `headBox`: the whole head stays in frame; the body may continue below the caption band, which is fine.
- **Vertical framing is narrow.** Two characters side by side push the camera far back; prefer depth staging (one character behind the other) or frame them one at a time. `bodyBox([a, b])` handles the distance; the composition is still your choice.
- **Occlusion is on you.** Check every shot for walls, banners, bunting, trees, building rows and other characters between the camera and the subject. Sets placed around a plaza must leave the camera paths clear (keep building rows far from where cameras go).
- **Blow-outs.** Bloom threshold 0.95, strength ~0.28. Keep point lights modest (lamp ~14, backlight ~7-10, fridge ~4). Give `MeshBasicMaterial` screens/pages/signs a grey colour (0xb8b8b8-0xc8c8c8) so they don't bloom to white. Emissive glows only via a separate emissive map (e.g. eyes only). Additive light beams stay below ~0.15 opacity.
- **Close-ups of a held prop:** compute its world position with `localToWorld` after `scene.updateMatrixWorld(true)`, frame it with `pointsBox`, and lower the arms so sleeves don't cover the face or the prop.
- **Poses near the face:** hands holding fire, phones or props in front of the face hide it. Raise arms out to the sides (`aLz` negative, `aRz` positive, elbows bent up) instead of forward.
- **Readable on-screen text** (lists, phone chats, laptop) is drawn on a canvas texture with Inter at large sizes; keep it out of the caption band.
- **Captions:** Inter 900, ~92 px, uppercase, thick dark stroke, centered at ~y=1395; active word highlighted (yellow narrator, cyan co-star) with a small scale pop; word gap ~50 px; wait for `document.fonts.load` before `window.ready`.
- **Lip movement:** co-star jaw or beak = loudness envelope during that character's phrases only. The narrator is voice-over and does not lip-sync.
- **Sitting/lying:** a robed character sitting upright reads as standing in a wide shot; lay it across the couch for wides, sit upright only in closer shots.
- **Big swarms:** instanced meshes (body + two wings) for hundreds of birds; keep them away from the lens or scale them down, and thin them out where the main subject must stay readable.
- **Ground:** the ground plane is one-sided, so a camera below y = 0 sees through it and characters float against the sky. Low angles must keep the camera at least ~0.35 above the ground (the kit's `fit()` eases the pitch toward level until it does); check every low-angle shot for visible ground.
- **Wide boxes push the camera far away** (vertical frame), often into a shop row or tree: a solid-colour or black frame means the camera is inside something. Raise the pitch, widen the FOV, change the yaw, or move a tree.
- **Determinism:** everything is a pure function of time `t`; use a hash for shake and particles, never `Math.random()`.
- Reset per frame: park all props and characters in a hidden group, reset poses, faces and set decorations, then let the active shot place what it needs.
- Shell commands: use absolute paths for `rm` (a `cd` before a relative `rm` glob is blocked).

## Engine spec (to rebuild if the kit is missing)

**Harness (`render.js`)**: Node + Playwright. Serve the folder over a local http server (ES modules don't load from file://). Launch Chromium with `channel: 'chromium'` and GPU flags (`--ignore-gpu-blocklist --enable-gpu`, plus `--use-angle=d3d11` on Windows), falling back to software flags `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist` when `CPU=1` or the GPU launch fails; viewport 1080x1920, wait for `window.ready`. `window.renderFrame(t)` renders and returns `canvas.toDataURL('image/jpeg', 0.93)`. Mode `still <times...>` writes JPEGs; mode `part <name> <f0> <f1>` pipes JPEG buffers to `ffmpeg -f image2pipe -c:v mjpeg -framerate 30 -i - -c:v libx264 -crf 18 -preset veryfast -pix_fmt yuv420p -r 30 parts/<name>.tmp.mp4`, renaming to `.mp4` only on exit code 0. `render-all.js` splits the frame range into 10 parts, runs `WORKERS` of them in parallel, skips parts that exist, concatenates and adds `mix.wav`. `index.html` has an import map for `three` and `three/addons/` and one 1080x1920 2D canvas `#out`.

**Renderer (`lib.js`)**: WebGLRenderer on an offscreen canvas (antialias, preserveDrawingBuffer), PCF shadow maps, ACES tone mapping exposure 1.15. EffectComposer on a 4-sample half-float target: RenderPass, UnrealBloomPass(0.28, 0.6, 0.95), OutputPass. Each frame: composer.render, then draw the GL canvas onto `#out` and paint 2D overlays (vignette, speed lines, impact text, confetti, hearts, flashes, shake, captions).

**Camera (`camera.js`)**: `fit(box, {yaw, pitch, zoom, fov, roll})` builds the camera basis from yaw/pitch (forward exactly along that direction), then binary-searches the distance so all 8 corners of the box project inside the safe rectangle (x within ±0.88 NDC; y between the top margin and the caption band), with the box centre placed at the middle of the safe rectangle by shifting the camera down along its up vector (not tilting). `zoom` multiplies that distance (clamped ≥ 1). `move(box, k, from, to, {ease, shake, spin})` interpolates yaw (shortest arc), pitch, zoom, fov and roll with smoothstep or ease-in-out and optional handheld drift, re-fitting every frame. `bodyBox`, `headBox`, `pointsBox` measure what to frame; `applyCam` sets the shared camera (position, up, lookAt, fov); `audit` reports the worst overshoot.

**Look**: `MeshToonMaterial` with a 4-step nearest-filter gradient map (95/165/225/255). Outlines by inverted hull: a second mesh on the same geometry with a BackSide dark basic material whose vertex shader pushes `position + normalize(normal) * 0.028`. All meshes cast and receive shadows; outline meshes don't.

**Human rig** (about 3.3 units tall): root > hips (y 1.2) > two legs (thigh capsule, knee pivot, shin capsule, rounded shoe + sole) and torso (rounded box, hood, pocket, strings) > two arms (shoulder pivot, upper capsule, elbow pivot, forearm, cuff, rounded-box hand, hand marker) and head (rounded box 1.24x1.1x1.1 radius 0.3 with a 6-material array so the +Z face carries a 512 px canvas face texture; ears; hair from rounded-box chunks: styles messy, long, bun, slick). Pose API `rig.set({aLx,aLz,eLx,eLz,aRx,aRz,eRx,eRz,lL,lR,kL,kR,lLz,lRz,tx,ty,tz,hx,hy,hz,y})`; negative arm x raises the arm forward; `rig.face({open,pupil,lx,ly,brow,raise,mouth,mo,blush,sweat,drip,happy,tear,pale})` with mouths smile, bigsmile, open, talk, flat, frown, o, grin, wavy.

**Co-star patterns**: Reaper (lathe robe with tattered hem, rope belt, wide sleeves, bone hands, skull face canvas plus eyes-only emissive canvas; face params glow, lx, ly, squint, brow, mo, happy, wide). Pigeon (ellipsoid body, iridescent neck, sphere head with orange eyes, sliding eyelids for a deadpan look, hinged lower beak for talking, wings on shoulder pivots that fold or flap, tail, orange legs; `set({hx,hy,hz,lid,mo,wing,flap,lean,bob,tuck})`). Giant robot (boxy segmented limbs on pivots, glowing visor and chest core, arm cannons; parts can pop off for a break-apart).

**Sets** (each a Group with its own hemisphere + shadowed key + rim lights, only the active one visible): living room day/night (wood floor, wallpaper, window with a drawn city, curtains, frames, shelf with books, rug, couch, floor lamp with point light, side table, plant that can wilt), kitchen day/night (checker floor, cabinets, sink with dish pile, window, fridge with opening door and inner light), entry hall (hinged door, stormy backdrop, backlight, sconce, coat hooks, shoe rack), studio (single tintable colour for montage shots), town square (sky dome with day / attack / golden textures, cobbles, plaza, fountain with animated droplets, Hero Academy with opening doors and sign, shop rows, lamps, bench, trees, bunting, birthday banner, statue pedestal with plaque). Props: scroll with canvas text, takeout box, splitting package, diary, laptop and phone with canvas screens, clock with hands, controllers, briefcase, paper stack, party hat, cape, flames, ice block, medal.

**Film file**: `SETS` map; `use(name)` shows one set and sets the background; `who(rig, x, y, z, ry, scale)` places a character in the active set; `put(prop, parent, pos, rot, scale)` attaches a prop (to the set or to a hand/torso); `shot(t0, t1, (u, t) => {...})` where `u` is time inside the shot; helpers `ss` (smoothstep), `win` (window), `pop` (overshoot), `lerp`, `L3`, `wp(obj, x, y, z)` (world position), `cam(pos, look, fov, roll)` (manual camera, rarely needed now), `proj(worldPoint)` for 2D overlay positions, `mark(point, text, size, colour)` for impact text.

**Sound effects (`sfx.py`)**: numpy synth at 44.1 kHz with an `add(time, samples, gain)` mixer and small generators (noise, sweeps, one-pole filters via scipy lfilter): knock, thunder, creak, whoosh, swish, slap, bass hit, boing, pop, squeak, click, clank, shing, bell, ding, 8-bit blip, heartbeat, riser, sting, trombone, buzz. Final `tanh` soft clip, stereo 16-bit WAV.

## Deliverable

One MP4 (H.264 + AAC, 1080x1920, 30 fps) with voice-over, captions and (if chosen) sound effects, plus a 3-4 line summary: length, what was verified, known compromises, and the offer to re-render individual shots or swap the audio.
